### JavaScript Directory

#### `js/audio.js` (200+ lines)
- **Web Audio API engine**
- **Features**:
  - Single shared `AudioContext`
  - Sample-accurate track synchronization
  - Per-track signal chain: Source → InGain → Pan → Fader → Analyser → SoloMute → Master
  - Playback control: play, pause, stop, seek
  - Tempo control (without pitch shift, preserves playback rate)
  - Master and per-track volume control
  - Stereo panning (-1 to 1)
  - Mute/Solo functionality
  - Peak and RMS metering
  - Real-time level tracking
  - RAF-based tick loop for continuous updates
- **Key Functions**:
  - `ensure()` — Initialize AudioContext
  - `loadFile(url)` — Load and decode audio file
  - `createTrack(track)` — Create signal chain for track
  - `startPlay(projectTime)` — Begin playback
  - `pausePlay()` — Pause at current position
  - `stopAll()` — Stop and reset
  - `seekTo(projectTime)` — Jump to position
  - `trackLevel(id)` — Get peak/RMS for display
  - `onTick(callback)` — Register RAF callback
  - `onState(callback)` — Register state change callback

#### `js/timeline.js` (200+ lines)
- **Peak envelope caching and waveform rendering**
- **Features**:
  - Pre-computed peak envelopes (max + RMS per pixel)
  - Peak cache with key-based lookup
  - Canvas-based waveform drawing
  - DPR (device pixel ratio) aware rendering
  - SMPTE timecode formatting (HH:MM:SS:FF)
  - HMS.ms formatting for internal use
  - Ruler rendering with adaptive tick intervals
- **Key Functions**:
  - `computePeaks(audioBuffer, pxPerSecond, duration)` — Calculate peak data
  - `clearPeaks(audioBuffer)` — Invalidate cached peaks
  - `drawWaveform(canvas, buffer, color, pxPerSecond)` — Render waveform with fill + outline
  - `drawRuler(canvas, pxPerSecond, duration, scrollLeft)` — Draw timecode ruler
  - `formatTC(sec, fps)` — Format as SMPTE (00:00:00:00)
  - `formatHMSms(sec)` — Format as HH:MM:SS.ms

#### `js/app.js` (500+ lines)
- **Main application logic and UI coordination**
- **State Management**:
  - Tracks array (id, name, path, buffer, volume, pan, mute, solo, etc.)
  - Playback position, duration, zoom level
  - Master volume, tempo, selected track
- **Initialization**:
  - Discovers audio files from `manifest.json` or defaults
  - Creates tracks from discovered files
  - Builds UI cards and lanes
  - Loads audio files into Web Audio buffers
  - Starts RAF loop for continuous UI updates
- **UI Components**:
  - Transport controls (Play/Pause, Stop)
  - Time readout (current / total in SMPTE)
  - Master controls (Volume, Tempo, Zoom)
  - Track cards (index, name, Mute, Solo, Volume, Pan)
  - Timeline ruler (SMPTE timecode)
  - Waveform lanes (one per track with scrolling)
  - Playhead (visual position indicator)
  - Status bar (playback state, sample rate, track count)
- **Interactions**:
  - Click/drag scrubbing on ruler or lanes
  - Two-finger pinch zoom on mobile
  - Keyboard shortcuts (Space, arrows, M, S, +/−)
  - Track selection (click card or lane)
  - Mute/Solo toggling
  - Volume and pan slider adjustments
  - Zoom level adjustment
  - Tempo adjustment
- **Responsive Updates**:
  - Real-time waveform redraw on zoom
  - Playhead position tracking
  - Auto-scroll to keep playhead in view
  - Meter updates (levels, peaks)

### Scripts Directory

#### `scripts/build.mjs` (120+ lines)
- **Production build script**
- **Process**:
  1. Remove existing `dist/` folder
  2. Create `dist/` and `dist/assets/`
  3. Minify JavaScript files with esbuild
  4. Concatenate JS in correct order (audio.js → timeline.js → app.js)
  5. Minify CSS with lightningcss
  6. Minify HTML with html-minifier-terser
  7. Rewrite asset paths in HTML
  8. Copy `vocals/` folder (all audio files)
  9. Copy `manifest.json`
  10. Create `.nojekyll` for GitHub Pages
  11. Report final size
- **Output**:
  - `dist/index.html` (~2.4 KB)
  - `dist/assets/app.bundle.min.js` (~19 KB)
  - `dist/assets/styles.min.css` (~10 KB)
  - `dist/vocals/` (all audio files, ~5.5 MB for example)
  - `dist/.nojekyll` (empty marker file)
- **Options**: No sourcemaps, minimal legal comments, tree-shaking enabled

#### `scripts/dev-server.mjs` (60+ lines)
- **Local HTTP development server**
- **Features**:
  - Listens on `localhost:8080` (configurable via PORT env var)
  - Serves all file types with correct MIME types
  - Path security checks (prevents directory traversal)
  - No caching (Cache-Control: no-cache)
  - CORS enabled (Access-Control-Allow-Origin: *)
  - Directory index fallback to `index.html`
  - Detailed logging
  - Cross-platform path handling

#### `scripts/generate-manifest.mjs` (30+ lines)
- **Discovers audio files in vocals/ folder**
- **Supported formats**: .mp3, .wav, .ogg, .m4a, .aac, .flac
- **Output**: `manifest.json` with sorted file list
- **Format**: `[{ name: "filename.mp3", path: "vocals/filename.mp3" }, ...]`
- **Error handling**: Reports if folder not found or no files found
- **Node.js cross-platform** (works on Windows, macOS, Linux)

#### `scripts/deploy-gh-pages.mjs` (40+ lines)
- **Publish dist/ to gh-pages branch**
- **Process**:
  1. Check that `dist/` exists (build first if needed)
  2. Use `gh-pages` npm package to publish
  3. Create or update `gh-pages` branch
  4. Set commit message with version and timestamp
  5. Display instructions for GitHub Pages configuration
- **Requires**: Push access to repository
- **Error handling**: Reports if build doesn't exist or publish fails

## Development Workflow

1. **Edit source files** (`js/`, `css/`, audio files in `vocals/`)

3. **Test locally**: `npm start` → `http://localhost:8080`

## Architecture Decisions

1. **Single AudioContext** — All tracks share one context for sample-accurate sync
2. **IIFE Modules** — Self-contained, no module bundler at runtime
3. **Canvas Rendering** — Hardware-accelerated, DPR-aware waveforms
4. **Peak Caching** — Pre-computed data to avoid recalculation on zoom
5. **RAF Loop** — 60 FPS playhead updates via requestAnimationFrame
6. **CSS Variables** — Responsive design via CSS custom properties
7. **Flexbox Layout** — Modern, flexible, mobile-friendly
8. **Touch Events** — Dedicated mobile interactions (pinch zoom, drag scrub)
9. **No External Libraries** — Pure vanilla JavaScript, no npm dependencies at runtime
10. **Progressive Enhancement** — Works without JavaScript for HTML/CSS structure

## Performance Optimizations

1. **Minified Assets** — 48% size reduction (JS, CSS, HTML)
2. **Peak Envelope Caching** — Avoid recalculating waveforms
3. **DPR Awareness** — Optimized canvas rendering for all screen densities
4. **Event Delegation** — Minimal event listener overhead
5. **RAF Batching** — Single loop for all animations
6. **CSS Containment** — Limited paint invalidation (where supported)
7. **Touch Action** — Prevent unwanted browser behaviors
8. **Lazy Loading** — Audio decoded on first play
